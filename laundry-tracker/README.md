# 洗涤工厂 - 产线排程与返洗跟踪系统

基于 Tauri + Svelte 构建的桌面端洗涤工厂管理系统，专注于解决产线排程和返洗跟踪的业务痛点。

## 业务背景

### 当前痛点
- **入口分散**：收衣单、返洗记录、交接回单各自独立
- **提醒薄弱**：异常单依赖截图和电话确认
- **历史难寻**：污损争议无证据、批次混洗难追溯
- **赔付模糊**：经常只能靠口头解释

### 解决方案
- **统一入口**：所有角色进入系统后知道该处理哪一段
- **接力式流程**：产线排程 ↔ 返洗跟踪 无缝衔接
- **证据留存**：问题处理全流程可追溯
- **离线可用**：基于本地存储，断网不影响业务

## 功能模块

### 1. 📊 总览 Dashboard
- 实时统计：总订单、处理中、质检中、返洗中、已完成、待处理问题
- 最新订单列表，快速跳转详情
- 动态时间线，记录所有关键操作

### 2. 🏭 产线排程 Production Line
- **看板模式**：7个工序阶段一目了然（待分拣 → 分拣中 → 洗涤中 → 烘干中 → 熨烫中 → 质检中 → 已完成）
- **批次管理**：多选订单创建批次，支持正常/返洗批次
- **一键推进**：批次开始/完成，自动推进订单状态
- **批量操作**：提高产线效率

### 3. 🔄 返洗跟踪 Rewash Tracker
- **返洗登记**：质检发现问题一键登记
- **次数统计**：第1次/第2次返洗自动标记
- **原因记录**：污渍/破损/褪色/其他分类记录
- **处理闭环**：标记完成后自动回到质检环节

### 4. ⚠️ 问题处理中心 Issues
- **争议留证**：支持照片和文字证据链
- **状态流转**：待处理 → 处理中 → 已解决 / 已升级
- **赔付管理**：记录赔付金额和处理方案
- **完整追溯**：从发现到解决全程可查

### 5. 📦 交接管理 Handover
- 门店送厂 / 工厂送店 双向交接
- 批量扫码确认
- 电子签名确认

### 6. 📱 扫码录入 Scanner
- 新建订单：手动录入衣物信息
- 条码查询：扫描条码快速定位订单
- 支持扫码枪：模拟键盘输入，按回车确认

### 7. 💾 数据管理 Import/Export
- **数据导出**：全量导出 JSON 备份
- **数据导入**：恢复或迁移数据
- **本地优先**：IndexedDB 本地持久化

## 技术架构

### 前端
- **框架**：Svelte 4 + TypeScript
- **构建**：Vite 5
- **样式**：原生 CSS + CSS 变量
- **存储**：IndexedDB (Dexie.js)

### 桌面端
- **框架**：Tauri 1.5
- **后端**：Rust (可选扩展)
- **特性**：
  - 本地文件系统访问
  - 原生对话框
  - 离线可用

### 数据模型
```
Order 订单
  ├─ ClothingItem 衣物明细 (含条码)
  ├─ ProcessRecord 工序记录 (时间线)
  ├─ RewashRecord 返洗记录
  └─ Issue 问题记录
     └─ Evidence 证据链

Batch 批次
  └─ 关联多订单

TimelineEvent 动态事件
  └─ 订单/批次/问题/返洗/交接 统一记录
```

## 业务流程示例

### 正常流程
```
门店收衣 → [扫码录入] → 待分拣 → 分拣归类
    → 创建批次 → 洗涤中 → 烘干中 → 熨烫中 → 质检
    → [合格] → 已完成 → 门店交接 → 已交付
```

### 返洗流程 (问题流)
```
质检发现问题
    ↓
[登记返洗] → 记录原因+证据 → 返洗队列
    ↓
创建返洗批次 → 重新洗涤 → 回到质检
    ↓
[再次质检] → 合格 → 正常流程
            ↓
        仍不合格 → 第N次返洗 / 升级问题
```

### 争议处理流程
```
发现问题 → [创建问题单] → 添加证据(照片/备注)
    ↓
指定处理人 → 调查 → 客户沟通
    ↓
[处理方案] → 协商赔付 → 记录金额 → 标记解决
    ↓
完整证据链留存，随时可查
```

## 实现取舍 (Trade-offs)

### 1. 本地优先 vs 云端同步
- **选择**：纯本地 IndexedDB 存储，无服务器
- **理由**：
  - 洗涤厂网络环境不稳定
  - 数据敏感性，不希望外传
  - 降低运维成本
- **代价**：多设备同步需要手动导出/导入

### 2. 简化流程 vs 完整ERP
- **选择**：聚焦核心流程（产线+返洗+问题）
- **理由**：
  - 现有系统太多入口，反而不好用
  - 先解决最痛的点
  - 小步快跑，逐步迭代
- **代价**：暂不支持财务、库存等模块

### 3. 手动扫码 vs 自动识别
- **选择**：支持扫码枪，但不做摄像头自动识别
- **理由**：
  - 扫码枪是行业标准设备，准确率高
  - 摄像头识别在工业环境不稳定
  - 降低开发复杂度
- **代价**：需要额外硬件投入

### 4. 固定工序 vs 自定义流程
- **选择**：7道固定工序（分拣→洗涤→烘干→熨烫→质检→完成→交付）
- **理由**：
  - 标准化流程降低培训成本
  - 统计分析更有意义
  - 避免流程混乱
- **代价**：特殊工艺灵活性不足

## 使用说明

### 首次使用
1. 打开应用，自动加载示例数据
2. 在「产线排程」点击订单卡片可以选择
3. 点击「创建批次」将选中订单入队
4. 批次可以「开始洗涤」和「完成批次」
5. 双击订单卡片可以查看详情

### 测试返洗流程
1. 进入「返洗跟踪」
2. 点击「登记返洗」
3. 选择订单，填写原因
4. 订单状态变为「返洗中」
5. 标记完成后回到「质检中」

### 测试争议处理
1. 进入「问题处理」
2. 点击任意问题单「处理」
3. 可以添加证据（照片/备注）
4. 填写处理方案和赔付金额
5. 标记状态为「已解决」
