# 地坪施工材料管理系统 - 实现取舍说明与后续扩展点

## 一、当前实现的核心取舍点

### 1.1 技术架构取舍

| 决策项 | 当前选择 | 取舍说明 | 替代方案 |
|--------|----------|----------|----------|
| **状态管理** | React Context + useReducer | ✅ 轻量级，无额外依赖，适合中小型业务<br>✅ 学习成本低，团队易上手<br>❌ 缺少 DevTools，调试不便<br>❌ 不支持中间件和时间旅行 | Redux Toolkit、Zustand、Jotai |
| **路由方案** | React Router v6 | ✅ 行业标准，功能完善<br>✅ 支持嵌套路由、动态路由<br>❌ 包体积较大（~20KB gzip） | TanStack Router、wouter |
| **样式方案** | TailwindCSS + 内联样式 | ✅ 开发效率高，无需切换文件<br>✅ 一致性好，约束设计系统<br>❌ HTML 类名冗长<br>❌ 复杂动画处理不便 | CSS Modules、Styled Components、Emotion |
| **图表库** | Recharts | ✅ React 原生，声明式 API<br>✅ 文档完善，社区活跃<br>❌ 包体积较大（~80KB gzip）<br>❌ 自定义图形能力有限 | ECharts、Chart.js、AntV G2 |
| **数据模拟** | 本地 TypeScript 常量 | ✅ 零成本，无需后端<br>✅ 类型安全，IDE 提示完善<br>❌ 无持久化，刷新丢失<br>❌ 无法模拟网络延迟 | Mock Service Worker (MSW)、MirageJS |

### 1.2 业务功能取舍

#### 角色权限设计
- **当前实现**：基于权限矩阵的前端控制，三个角色（项目负责人/质检工程师/班组长）
- **取舍点**：
  - ✅ 仅前端控制，快速验证业务流程
  - ✅ 角色差异化明显，避免"看起来都一样"的问题
  - ❌ 无后端校验，存在安全隐患（生产环境必须加后端鉴权）
  - ❌ 权限粒度较粗（页面级），未做到按钮级细粒度控制

#### 业务状态机
- **当前实现**：线性状态流转，支持基本的状态转换校验
- **取舍点**：
  - ✅ 简单直接，符合地坪施工的实际流程
  - ✅ 状态转换有明确的操作人、时间戳记录
  - ❌ 不支持并行状态、子状态等复杂场景
  - ❌ 无状态回滚机制

#### 连续处理动作流
- **当前实现**：页面内操作联动，列表页可直接处理待办
- **取舍点**：
  - ✅ 看板可下钻到具体单据，形成"总览→详情→处理"的完整闭环
  - ✅ 待办事项聚合展示，无需切换页面
  - ❌ 缺少真正的工作流引擎，无法配置审批链
  - ❌ 无任务分配、抢单、转派等协作功能

### 1.3 用户体验取舍

#### 界面设计
- **当前实现**：工业风深色主题，功能优先
- **取舍点**：
  - ✅ 信息密度高，适合专业用户
  - ✅ 操作路径短，效率优先
  - ❌ 视觉层次较平，新用户学习成本高
  - ❌ 缺少引导式交互、空状态设计

#### 移动端适配
- **当前实现**：仅桌面端优化
- **取舍点**：
  - ✅ 聚焦核心场景，桌面端是工地办公室的主要使用场景
  - ❌ 班组长现场签收需要移动端（后续优先级高）

## 二、真实样例数据说明

### 2.1 正常流样例

#### 样例1：环氧树脂材料正常发货签收
**发货单**：FH20240501-001
- **流程**：创建发货单 → 项目负责人审核 → 出库 → 运输 → 班组长签收 → 回单核验通过
- **关键数据**：
  - 材料：环氧树脂 1000kg + 固化剂 500kg
  - 发货量与签收量完全一致
  - 无差异记录，无争议
- **角色路径**：
  - 质检工程师：创建发货单
  - 项目负责人：审核通过
  - 班组长：现场签收，确认无误
  - 质检工程师：回单核验通过

### 2.2 问题流样例

#### 样例2：固化剂数量差异处理
**发货单**：FH20240515-003
**回单**：HD20240516-003
- **问题**：签收时发现固化剂少 50kg
- **处理流程**：
  1. 班组长签收时标记"数量差异"，上传照片凭证
  2. 系统自动触发预警，推送至项目负责人和质检工程师
  3. 质检工程师发起差异调查
  4. 责任判定：物流方责任（运输过程丢失）
  5. 创建争议单，进入索赔流程
  6. 补发货 50kg 固化剂
- **数据痕迹**：
  - 差异记录：50kg，责任方=物流
  - 操作日志：完整记录每个节点的操作人、时间、备注
  - 争议单：ZY20240517-001，状态=处理中

#### 样例3：基层处理不达标返工闭环
**返工单**：RG20240520-001
- **问题**：质检工程师复查发现基层处理不达标
- **处理流程**：
  1. 质检工程师创建返工单，指定原因"基层处理不达标"
  2. 系统自动关联对应发货单、回单
  3. 班组长接收返工任务，安排整改
  4. 整改完成后提交复查申请
  5. 质检工程师复查通过，闭环
- **数据关联**：
  - 返工原因分类留存，可统计分析
  - 返工工时、材料消耗记录，影响班组结算
  - 整改前后照片对比

## 三、后续扩展点

### 3.1 高优先级扩展（P0）

#### 1. 后端服务接入
- **位置**：`src/store/` 层、`src/data/` 层
- **内容**：
  - 接入真实 REST API 或 GraphQL
  - 添加请求拦截器、响应拦截器
  - 实现 Token 认证、权限校验
  - 添加 SWR / React Query 做数据缓存
- **影响**：需要重构数据获取层，业务组件层改动较小

#### 2. 移动端适配
- **位置**：全局样式、布局组件
- **内容**：
  - 响应式布局优化（Tailwind 断点）
  - 移动端专用组件（底部导航、滑动操作、拍照上传）
  - PWA 支持，离线功能
- **影响**：布局组件重构，页面组件适配

#### 3. 工作流引擎
- **位置**：`src/hooks/useWorkflow.ts`、新建 `src/workflow/` 目录
- **内容**：
  - 引入 XState 或 LogicFlow
  - 支持可视化流程配置
  - 支持会签、或签、转派、退回等复杂场景
  - 审批链动态配置
- **影响**：状态管理逻辑重构，业务流程解耦

### 3.2 中优先级扩展（P1）

#### 4. 报表与数据分析
- **位置**：新建 `src/pages/Reports/` 目录
- **内容**：
  - 材料损耗分析报表
  - 返工原因统计与趋势分析
  - 班组绩效排行榜
  - 供应商质量评级
  - 自定义报表导出（Excel、PDF）
- **依赖**：需要图表库增强、后端聚合查询

#### 5. 消息通知中心
- **位置**：`src/components/layout/Header.tsx`、新建 `src/notifications/`
- **内容**：
  - WebSocket 实时推送
  - 消息分类（预警、待办、通知）
  - 已读/未读状态
  - 消息中心历史记录
  - 邮件、短信、企业微信推送集成
- **影响**：需要后端消息队列支持

#### 6. 文件与凭证管理
- **位置**：新建 `src/components/FileUpload/`、`src/components/ImageViewer/`
- **内容**：
  - 多图上传、压缩、预览
  - OCR 识别回单信息
  - 电子签名
  - 文件分类存储、权限控制
- **依赖**：需要对象存储服务（OSS/S3）

### 3.3 低优先级扩展（P2）

#### 7. 第三方系统集成
- **内容**：
  - ERP 系统对接（材料库存同步）
  - 财务系统对接（结算数据同步）
  - IoT 设备对接（地磅数据自动采集、温湿度监控）
  - GIS 地图集成（运输轨迹追踪）

#### 8. AI 智能辅助
- **内容**：
  - 智能差异原因推荐
  - 材料用量预测
  - 返工风险预警
  - 自然语言搜索

#### 9. 多租户与组织架构
- **内容**：
  - 多项目、多公司隔离
  - 部门、岗位管理
  - 数据权限（只能看自己的项目）
  - 审计日志

## 五、关键技术债务清单

1. **类型安全**：部分 `any` 类型需要具体化，`tsconfig` 严格模式开启
2. **错误处理**：缺少全局错误边界、网络错误重试机制
3. **性能优化**：列表虚拟化、图片懒加载、Bundle 分包
4. **测试覆盖**：单元测试、E2E 测试缺失
5. **代码规范**：ESLint 规则完善、Prettier 格式化、Git Hooks
6. **国际化**：硬编码中文字符串需要抽取
