# 🎭 乐器租赁系统 - 角色切换说明

## 👥 角色体系

系统设计了三种角色，基于 **RBAC（基于角色的访问控制）** 模型，每个角色拥有明确的权限边界。

### 角色定义

| 角色 | 英文标识 | 主要职责 | 典型用户 |
|------|----------|----------|----------|
| 门店老板 | `STORE_OWNER` | 审批、结算、全局查看、争议处理 | 店长、店主 |
| 租赁顾问 | `RENTAL_ADVISOR` | 租出、归还、客户对接、发起申诉 | 前台、销售 |
| 维修师傅 | `MAINTENANCE_TECH` | 维修记录、损坏鉴定、费用登记 | 维修技师 |

## 🔄 角色切换方式

### 方式一：使用不同账号登录（推荐）

系统预置了三个测试账号，使用不同账号登录即可切换角色：

```bash
# 登录为老板（全部权限）
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"owner","password":"123456"}'

# 登录为顾问（租出/归还/发起申诉）
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"advisor","password":"123456"}'

# 登录为师傅（维修/鉴定）
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"tech","password":"123456"}'
```

登录成功后，将返回的 `token` 填入后续请求的 `Authorization` 头即可。

### 方式二：切换请求头 Token

在 HTTP 请求头中替换 Token 即可切换角色身份：

```http
Authorization: Bearer <owner-token>
# 或
Authorization: Bearer <advisor-token>
# 或
Authorization: Bearer <tech-token>
```

## 🎯 各角色可操作的典型场景

### 🏪 门店老板 (STORE_OWNER)

**核心能力**：争议处理、押金结算、全局管控

**典型操作流程**：
1. 查看所有租赁单、押金单、损坏申诉
2. 处理客户申诉（驳回或通过）
3. 进行押金结算（退款/扣款）
4. 查看审计日志，追溯操作历史
5. 补录历史备注（需要填写补录原因）
6. 查看维修费用汇总

**可访问的关键接口**：
- `POST /api/damage-claims/:id/reject` - 驳回客户申诉
- `POST /api/damage-claims/:id/resolve` - 通过申诉，重新判责
- `POST /api/deposits/:id/settle` - 押金结算
- `POST /api/notes/supplement` - 补录备注
- `GET /api/audit-logs` - 审计日志
- `GET /api/maintenances/summary` - 费用汇总

---

### 💼 租赁顾问 (RENTAL_ADVISOR)

**核心能力**：租出、归还、客户对接

**典型操作流程**：
1. 为客户创建租赁单
2. 客户归还时检查乐器状态
3. 如发现损坏，发起损坏申诉
4. 记录客户申诉意见
5. 添加业务备注

**可访问的关键接口**：
- `POST /api/rentals` - 创建租赁单
- `POST /api/rentals/:id/return` - 归还乐器
- `POST /api/damage-claims` - 创建损坏申诉
- `POST /api/damage-claims/:id/dispute` - 记录客户申诉
- `GET /api/rentals` - 租赁单列表
- `GET /api/rentals/instruments` - 乐器列表

---

### 🔧 维修师傅 (MAINTENANCE_TECH)

**核心能力**：维修记录、损坏鉴定

**典型操作流程**：
1. 创建维修单
2. 对损坏进行专业鉴定
3. 登记维修费用（配件费+人工费）
4. 完成维修，更新乐器状态
5. 添加维修技术备注

**可访问的关键接口**：
- `POST /api/maintenances` - 创建维修单
- `POST /api/maintenances/:id/complete` - 完成维修
- `GET /api/maintenances` - 维修单列表
- `GET /api/damage-claims` - 损坏申诉（用于鉴定参考）

## 🔒 权限校验机制

### 中间件实现

系统通过两层中间件实现权限控制：

1. **认证中间件** (`authenticate`)
   - 验证 JWT Token 有效性
   - 解析用户信息（ID、角色等）
   - 将用户信息挂载到 `req.user`

2. **权限中间件** (`requirePermission`)
   - 校验当前用户角色是否拥有请求的权限
   - 权限不足返回 `403 Forbidden`

### 示例：接口权限配置

```typescript
// 驳回申诉 - 仅老板可操作
router.post(
  '/:id/reject',
  authenticate,
  requirePermission('damage:resolve'),
  validate(rejectDisputeSchema),
  async (req, res, next) => {
    // 业务逻辑
  }
)
```

### 权限不足响应

```json
{
  "success": false,
  "error": {
    "code": 403,
    "message": "权限不足，该操作仅门店老板可执行"
  }
}
```
