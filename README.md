# 乐器租赁系统 - 订单租出与归还验收链路

## 项目概述

本系统实现了乐器租赁从订单租出到归还验收的完整链路追踪，解决了传统分散管理模式下的数据断层、责任不清、结算混乱等问题。

## 核心功能

### 🔗 订单链路追踪
- 完整的订单生命周期可视化（租出办理 → 租赁中 → 归还验收 → 损坏判定 → 维修流程 → 押金结算）
- 时间线展示所有操作记录和状态流转
- 可追溯的责任判定依据

### 👥 角色差异化视图
| 角色 | 权限范围 | 核心工作台 |
|------|----------|------------|
| **门店老板 (boss)** | 全功能权限 + 争议裁定 | 全局数据概览、押金结算审批、争议处理 |
| **租赁顾问 (consultant)** | 租出办理、归还验收、复检确认 | 待归还列表、超时预警、复检工作台 |
| **维修师傅 (repair)** | 维修任务接单、进度更新、提交复检 | 维修任务看板、待修/维修中/待复检分区 |

### 🛠️ 异常处理机制
- **超时预警**：今日到期、已超时订单高亮显示
- **损坏判定**：轻微/中度/严重三级，客户责任/自然损耗/质量问题/待判定四类
- **争议流程**：标记争议 → 老板裁定 → 更新责任方
- **维修退回**：复检不通过可退回重修并记录原因

### 💰 押金结算体系
- 扣款类型：租金、损坏赔偿、维修费、超时费、其他
- 扣款明细可编辑，支持备注说明
- 结算单审批流程，可查看历史记录

## 演示数据说明

系统内置了以下演示场景，可直接体验完整流程：

### 典型异常场景
1. **超时订单 - ORD-2024002**
   - 状态：租赁中（已超时3天）
   - 可操作：归还验收

2. **损坏待判定 - ORD-2024003**
   - 状态：验损中
   - 中度损坏，责任待判定
   - 可操作：标记争议/创建维修任务

3. **争议处理 - ORD-2024004**
   - 状态：争议待裁
   - 客户不认可损坏赔偿
   - 可操作：老板裁定责任

4. **维修退回 - ORD-2024005**
   - 状态：维修中（已退回）
   - 维修未通过复检
   - 可操作：维修师傅重新处理

5. **押金待结算 - ORD-2024006**
   - 状态：结算中
   - 有损坏赔偿扣款
   - 可操作：老板审批结算

6. **学校合作订单 - ORD-2024007**
   - 类型：学校合作
   - 分期付款计划
   - 可查看回款进度

## 刻意简化的部分

1. **真实后端接口**
   - 所有数据存储在前端 Pinia Store 中
   - 刷新页面数据会重置
   - 生产环境需对接真实 API

2. **文件上传**
   - 租前/验损拍照为模拟功能
   - 未实现真实图片上传和存储
   - 生产环境需接入 OSS/文件服务器

3. **支付系统**
   - 押金扣款、退款为模拟流程
   - 未对接真实支付网关
   - 生产环境需集成支付系统

4. **消息通知**
   - 侧边处理台为静态展示
   - 未实现实时推送（WebSocket/SSE）
   - 生产环境建议接入消息队列

5. **权限控制深度**
   - 路由级别权限控制
   - 未实现数据行级权限（如顾问只能看自己的订单）
   - 生产环境需完善数据隔离

6. **数据持久化**
   - 未接入数据库
   - 演示数据硬编码在 types/index.ts
   - 生产环境需设计完整数据库表结构

## 技术栈

- **Vue 3** - 组合式 API + `<script setup>`
- **TypeScript** - 完整类型定义
- **Vite** - 构建工具
- **Pinia** - 状态管理
- **Vue Router** - 路由 + 角色权限
- **Tailwind CSS** - 样式框架
- **Lucide Vue** - 图标库
