# 高尔夫练习场会员储值与消耗对账系统

> 解决高尔夫练习场信息分散、对账困难、交接班卡壳、投诉回查无依据等核心痛点的一体化管理系统。

## 🌟 核心特性

### 🔗 信息一体化
- **全链路打通**：会员储值 → 球道预约 → 到场签到 → 自动扣减 → 器材借还 → 归还验收 → 日终对账，全程数据打通
- **过程留痕**：所有关键操作自动记录日志，包含操作前后数据对比，告别翻截图和语音
- **消耗口径统一**：本金/赠送金分离，扣减优先级可配置，节假日/周末系数自动计算

### 👥 三角色入口
| 角色 | 核心功能 |
|------|----------|
| **前台** | 会员搜索、储值充值、球道预约、签到扣减、器材借还、当班流水 |
| **教练主管** | 预约日历、学员管理、课时确认、教学器材管理 |
| **场馆经理** | 数据概览、对账中心、异常处理、操作审计、口径配置 |

### 🔍 多条件筛选（扎实不做空壳）
- 文本模糊搜索、下拉单选、多选标签
- 日期范围、数值范围
- 已选条件标签化，支持单独删除
- 高级筛选折叠，保持界面简洁
- 后端动态 SQL 构建，自动防注入

### 📝 过程留痕（投诉回查有依据）
- **全链路时间线**：会员储值、消费、预约、器材、异常按时间聚合展示
- **操作日志审计**：360° 无死角记录，支持按人、按模块、按时间多维度回查
- **异常工单内嵌时间线**：处理投诉时自动展示该会员所有操作记录

## 🛠 技术栈

| 层级 | 技术选择 |
|------|----------|
| 前端 | **Next.js 14** (App Router) + **TypeScript** + **TailwindCSS 3** + **Zustand** |

## 🎯 设计亮点

### 1. 储值账户设计
- **本金/赠送金分离**：赠送金有有效期，扣减优先级可配置
- **会计恒等式校验**：每笔交易后自动校验余额准确性
- **多维度统计**：本金、赠送金、冻结金额分别统计

### 2. 多条件筛选
- **约定优于配置**：`_like` / `_start` / `_end` / `_min` / `_max` 后缀约定
- **动态 SQL 构建**：`buildWhereClause()` 统一处理，自动防注入
- **前端体验**：已选条件标签化，支持单独删除，交互流畅

### 3. 操作留痕
- **统一日志中间件**：`logAudit()` 自动记录操作前后数据
- **JSON 差异对比**：前端展示操作前后 JSON 格式差异
- **全链路时间线**：5 类数据按时间聚合，投诉回查一目了然

### 4. 对账流程
- **自动汇总**：一键生成当日对账数据
- **异常标记**：不匹配交易自动标红
- **逐笔调账**：支持对单条交易调整，记录调账原因
- **审核锁定**：审核通过后数据不可修改

## 📌 实现取舍点摘要

### 为什么选 SQLite？
- ✅ 单机场馆零运维，备份就是复制文件
- ✅ 10 万级数据量性能足够
- ⚠️ 未来多场馆需要迁移到 PostgreSQL（数据访问层已抽象，迁移成本低）

### 为什么用 JWT？
- ✅ 无状态，前后端分离实现简单
- ✅ 支持多端共享（未来小程序/App）
- ⚠️ Token 签发后无法主动撤销（可引入黑名单机制）

### 为什么日终人工审核？
- ✅ 场馆规模不大，日对账可接受
- ✅ 人工可以处理边缘情况
- ⚠️ 未来可升级为定时任务自动对账 + AI 异常识别

## 🔮 后续扩展方向

3. **智能对账**：AI 识别异常交易，自动预警
4. **库存管理**：商品销售、采购入库、库存盘点
5. **数据分析**：会员画像、球道利用率、教练绩效分析
6. **财务深化**：发票管理、营收报表、对接会计系统
