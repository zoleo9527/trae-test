# 剧院管理系统 - 演出排期与后台联排全链路解决方案

## 系统概述

本系统解决了传统剧院管理中「演出排期、票务团单、后台联排」数据分散、断层的问题，通过 **chainId 链条机制** 将三者串联，实现全链路追踪。配合角色视图和侧边任务处理台，让不同角色打开就能看到今天该处理什么、哪里超时、哪里被退回。

## 🎯 核心功能

### 1. 链条追踪 🔗

通过 `chainId` 将「演出排期 → 票务团单 → 后台联排 → 任务处理」串联成一条可追溯的完整链路：

- **排期** 创建时自动生成 `chainId`
- **团单** 归属到对应演出的链条下
- **联排** 同样归属到链条
- **任务**（审批、退票、变更等）全部关联到链条

在「链条追踪」页面可以完整查看某场演出的全生命周期数据。

### 2. 角色视图 👥

不同角色登录后看到不同的导航菜单和数据范围：

- **剧院经理**：全部功能 + 审批任务
- **票务主管**：团单管理 + 退票/结算任务
- **后台统筹**：联排管理 + 场地协调任务

### 3. 侧边任务处理台 📋

右侧常驻任务面板，显示当前用户待处理任务，支持：

- 按状态筛选（全部/待处理/处理中）
- 优先级颜色标识（紧急/高/中/低）
- 超时任务红色标记
- 点击弹窗快速处理

### 4. 异常处理流程 ⚠️

系统预置了多类异常场景的处理流程：

| 异常场景 | 触发方式 | 处理流程 |
|---------|---------|---------|
| **退票申请** | 团单已付款后申请 | 票务主管审批，支持通过/拒绝，需填写原因 |
| **排期变更** | 修改已排期演出时间/场地 | 自动生成变更任务通知相关人员 |
| **加场申请** | 售票情况良好时申请 | 剧院经理审批 |
| **联排问题** | 联排现场上报问题 | 后台统筹标记解决 |
| **场地冲突** | 彩排时间重叠 | 生成紧急任务协调 |
| **费用结算** | 演出完成后结算 | 票务主管处理结算流程 |

- **任务**：紧急协调场地时间

- **演出**：绿野仙踪（六一儿童节场）

- **演出**：天鹅湖技术联排（进行中）
- **问题上报**：
  - ✅ 左侧追光灯角度偏移（已解决）
  - ⏳ 音响有杂音（待处理）
- **操作**：登录 backend 账号 → 联排管理 → 查看详情 → 标记解决

## ⚠️ 刻意简化的部分

为了演示核心逻辑，本系统做了以下简化：

1. **数据持久化**：使用内存存储，服务重启数据重置

2. **实时通知**：未实现 WebSocket 推送
   - 生产环境建议：Socket.io 或 Server-Sent Events

3. **文件上传**：未实现附件上传功能

5. **操作日志**：仅任务有简单历史记录

6. **报表导出**：未实现数据导出功能

## 🔗 API 接口清单

### 认证
- `POST /api/auth/login` - 登录
- `GET /api/auth/me` - 获取当前用户

### 演出排期
- `GET /api/performances` - 获取演出列表
- `GET /api/performances/:id` - 获取演出详情
- `GET /api/performances/chain/:chainId` - 获取链条全数据
- `POST /api/performances` - 创建演出
- `PUT /api/performances/:id` - 更新演出
- `PATCH /api/performances/:id/status` - 更新状态

### 票务团单
- `GET /api/orders` - 获取团单列表
- `POST /api/orders` - 创建团单
- `POST /api/orders/:id/refund-request` - 申请退票
- `POST /api/orders/refund/:taskId/process` - 处理退票

### 后台联排
- `GET /api/rehearsals` - 获取联排列表
- `POST /api/rehearsals` - 创建联排
- `POST /api/rehearsals/:id/issues` - 上报问题
- `PATCH /api/rehearsals/:rid/issues/:iid/resolve` - 解决问题

### 任务处理
- `GET /api/tasks/my` - 获取我的任务
- `POST /api/tasks/:id/approve` - 审批通过
- `POST /api/tasks/:id/reject` - 审批拒绝
- `POST /api/tasks/:id/complete` - 标记完成

## 📞 常见问题

**Q: 数据会保存吗？**  
A: 不会，本演示使用内存存储，服务重启后数据重置。

**Q: 如何切换角色测试？**  
A: 点击左侧「退出登录」，使用不同账号重新登录。

**Q: 任务超时如何判断？**  
A: 任务截止日期早于当前日期即标记为超时。

**Q: 链条ID是什么？**  
A: 每场演出创建时生成的唯一标识，用于串联排期、团单、联排、任务。

## 🎯 核心设计理念

1. **数据不分散**：通过 chainId 机制把所有关联数据串起来
2. **角色不混用**：不同角色看到不同视图，专注自己的工作
3. **任务不遗漏**：侧边常驻任务面板，优先级+超时一目了然
4. **操作有依据**：所有审批操作需填写备注，历史记录可追溯
5. **异常有流程**：退票、改期、冲突等都有标准处理流程
