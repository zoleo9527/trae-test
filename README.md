# 高尔夫练习场-巡场记录与投诉跟进系统

## 项目概述

本系统旨在解决高尔夫练习场巡场记录、投诉跟进、球道预约、储值扣减和器材借还信息割裂的问题，建立完整的业务链路，实现从发生到处理的全流程可追溯。

## 技术栈

- **框架**: Nuxt 3 (Vue 3 + TypeScript)
- **状态管理**: Pinia
- **样式框架**: Tailwind CSS
- **日期处理**: dayjs
- **工具库**: VueUse

## 核心功能

### 1. 巡场记录管理
- 巡场记录创建、提交、审核、驳回
- 多状态流转（草稿→待审核→已通过/已驳回→处理中→已完成）
- 问题项跟踪与关联投诉
- 历史备注与状态时间线

### 2. 投诉跟进管理
- 投诉记录创建、分配、处理、跟进
- 关联巡场记录、预约、器材信息
- 完整上下文展示（发生了什么、谁处理了、处理结果）
- 内部/公开备注区分

### 3. 球道预约管理
- 预约创建、checkin、checkout
- 关联储值账户自动扣减
- 器材租借与归还关联
- 日历视图联动展示

### 4. 储值账户管理
- 储值账户充值、消费、冻结
- 消耗口径一致性展示（每笔消费明细）
- 折扣规则说明
- 交易记录与预约关联

### 5. 器材借还管理
- 器材借出、归还验收
- 归还状态选择（完好/一般/较差/损坏）
- 押金处理逻辑
- 逾期提醒与历史追溯

## 业务链路说明

### 完整业务流示例

1. **预约阶段**：前台创建预约 → 选择储值账户 → 预约时租借器材
2. **消费阶段**：客户到场 checkin → 实际消费后 checkout → 储值自动扣减（含明细）
3. **巡场阶段**：教练主管巡场 → 发现问题 → 创建巡场记录 → 提交审核
4. **投诉阶段**：客户投诉 → 关联对应巡场记录/预约/器材 → 分配处理人 → 跟进处理 → 关闭
5. **归还阶段**：器材归还验收 → 选择状态 → 押金处理 → 损坏自动创建维修单

### 关联关系设计

- 投诉可关联：巡场记录、预约、器材
- 巡场记录可关联：投诉、预约
- 预约可关联：储值账户、器材租借
- 所有记录支持：状态时间线、历史备注、责任人追踪

## 核心痛点解决方案

### 1. 消耗口径不一致
- **问题**: 储值扣减时费用明细不清晰，折扣计算不透明
- **方案**: 每笔消费记录详细的 `consumptionDetail`，包含：
  - 球道费、教练费、器材费等分项
  - 原价、折扣率、折后价
  - 关联预约编号，可跳转查看

### 2. 投诉回查无上下文
- **问题**: 处理投诉时不知道之前发生了什么、谁处理过
- **方案**: 投诉详情页展示：
  - 关联的巡场记录、预约、器材信息
  - 完整的处理时间线（状态变化、操作人、时间）
  - 内部备注（仅内部可见）和公开备注（客户可见）

### 3. 归还验收容易漏
- **问题**: 器材归还时不检查状态，出现损坏无法追责
- **方案**: 归还流程强制：
  - 必须选择归还状态（完好/一般/较差/损坏）
  - 损坏时押金不予退还并自动创建维修单
  - 预约 checkout 时自动检查器材是否已归还
  - 逾期器材高亮显示并发送提醒

## 边界说明（简化处理部分）

### 已简化的功能

1. **真实后端对接**
   - 当前使用前端模拟数据（Pinia + localStorage）
   - 真实场景需要对接后端 API
   - 建议：后续接入真实 API 时，store 层只需替换实现

2. **用户认证系统**
   - 当前角色切换为模拟切换，无真实登录验证
   - 密码、权限的后端校验未实现
   - 建议：后续接入 OAuth 或 JWT 认证

3. **支付系统**
   - 储值充值、消费为模拟操作，无真实支付流程
   - 微信/支付宝等支付渠道未接入
   - 建议：后续接入支付网关

4. **消息推送**
   - 当前仅实现站内通知和 Toast 提示
   - 短信、微信、邮件等外部通知未实现
   - 建议：后续接入消息推送服务

5. **数据持久化**
   - 当前数据保存在 localStorage，刷新页面数据重置
   - 建议：后续接入后端数据库

6. **报表导出**
   - 当前仅支持页面查看，无 Excel/PDF 导出功能
   - 建议：后续添加报表导出功能

7. **多场馆支持**
   - 当前为单场馆设计
   - 建议：后续需要时添加场馆维度的数据隔离
