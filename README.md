# 茶叶经销-客户试饮与回访跟进管理系统

## 项目概述

本系统是针对茶叶经销业务的客户试饮与回访跟进管理系统，解决以下核心问题：
- 试饮记录分散、回访跟进脱节
- 订单审批流程不规范、驳回原因无记录
- 异常情况（批次混发、价格口径乱）无证据链
- 各角色协作无统一平台

## 技术栈

- **前端**: React 18 + Ant Design 5 + React Router 6
- **后端**: Node.js + Express + better-sqlite3
- **数据库**: SQLite（轻量级，无需额外部署）
- **拖拽**: @dnd-kit 实现回访任务拖拽排班

## 快速开始

### 安装依赖

```bash
# 安装后端依赖
npm install

# 安装前端依赖
cd client
npm install
cd ..
```

### 初始化数据库

```bash
# 初始化数据库表结构
npm run init-db

# 插入样例数据
npm run seed-data
```

### 启动服务

```bash
# 启动后端服务（端口3001）
npm run dev

# 启动前端服务（端口3000，另开终端）
npm run client
```

访问 http://localhost:3000 即可使用系统。

## 样例数据说明

### 正常流程样例 - 祥云茶楼（刘总）

**流程路径**: 试饮 → 回访 → 下单 → 审批 → 发货 → 异常处理（批次混发）→ 解决

1. **试饮记录**: 西湖龙井-明前特级 2份，满意度5星
2. **回访记录**: 两次回访（电话+拜访），客户表示满意
3. **订单**: 10罐龙井，10%折扣，¥5220
4. **审批**: 负责人审批通过
5. **发货**: 仓管发现原批次库存不足，调用备用批次，**上报异常（批次混发）**
6. **异常处理**: 已电话告知客户，备注记录

### 待处理流程样例 - 品茗轩（周经理）

**流程路径**: 试饮 → 回访 → 下单 → 待审批 + 价格口径异常

1. **试饮记录**: 武夷大红袍-岩韵 3份，满意度4星（价格偏高）
2. **回访记录**: 微信发送活动信息，客户考虑中
3. **订单**: 20盒铁观音，15%折扣，¥6120
4. **异常**: 业务员报价时提到"活动价"，但系统无此活动，**价格口径异常待处理**

### 问题流程样例 - 祥云茶楼（普洱订单）

**流程路径**: 下单 → 审批驳回 → 补录说明

1. **订单**: 50饼普洱，要求20%折扣
2. **审批**: 负责人驳回，原因：折扣率20%超出权限（最高15%）
3. **补录**: 业务员补充说明客户是老客户介绍且订购量大

### 拖拽测试场景

- **同日期排序**: 李华今日有3条待回访任务（09:00/10:30/14:00），可拖拽调整顺序
- **跨日期移动**: 王芳明日有1条、后天1条、大后天1条任务，可拖拽到其他日期
- **空列拖入**: 任意日期列即使无任务也接收拖拽，拖入后自动放到末尾

## 核心功能模块

### 1. 工作台 (Dashboard)
- 关键数据统计卡片
- 今日回访任务列表
- 待审批订单提醒
- 待处理异常预警

### 2. 客户管理
- 客户档案（分级管理：VIP/普通/潜在）
- 客户历史试饮记录
- 客户历史订单
- 客户备注（支持补录标记）

### 3. 试饮记录
- 试饮档案（产品、数量、日期、负责人）
- 满意度评分
- 关联回访任务
- 试饮备注

### 4. 回访排班（拖拽）⭐
- **按业务员+日期范围**的看板视图
- **拖拽调整**回访任务顺序和日期（持久化保存）
- 同日期列内排序、跨日期移动、空列拖入均支持落库
- 新建回访任务（关联试饮）
- 完成回访（记录内容、结果、下次回访）

### 5. 订单管理
- 订单全生命周期跟踪
- 折扣计算
- 订单审批流程
- 订单备注与异常记录

### 6. 审批中心
- 待审批订单列表（快速通过/驳回）
- 审批历史记录
- **驳回原因必填**

### 7. 异常处理中心 ⭐
- 异常类型：批次混发、价格口径、货物破损、其他
- 异常上报与处理
- **证据链记录**（描述+处理结果）
- 支持展开查看详情

## 数据留痕设计

所有关键操作均有完整记录：

| 数据类型 | 记录内容 | 位置 |
|---------|---------|------|
| 审批记录 | 审批人、动作、原因、时间 | 订单详情 → 审批时间线 |
| 异常记录 | 上报人、类型、描述、处理人、结果 | 订单详情 → 异常记录 |
| 备注记录 | 创建人、内容、是否补录、时间 | 各模块备注区 |
| 状态变更 | 状态流转时间节点 | 订单详情 → 步骤条 |

## 当前实现取舍点

### 1. 技术架构取舍
- ✅ **SQLite替代MySQL**: 轻量无需部署，适合快速验证；后续可平滑迁移
- ✅ **无完整用户认证**: 预设角色演示，专注业务流程；后续加JWT认证
- ✅ **单页应用**: 前后端分离，开发效率高

### 2. 业务流程取舍
- ✅ **简化的SKU管理**: 产品只有基础信息，后续扩展多规格多批次库存
- ✅ **无支付模块**: 聚焦试饮-回访-订单流程，支付可后续对接
- ✅ **固定折扣审批**: 目前无分级权限配置，统一负责人审批
- ✅ **单产品订单**: 目前一单一品，后续扩展购物车模式

### 3. 交互设计取舍
- ✅ **拖拽排班已落库**: 回访任务拖拽支持同日期排序和跨日期调度均保存到数据库，刷新后顺序保留；后续可扩展批量分配业务员
- ✅ **简化的看板视图**: 按日期列展示，不做复杂的资源调度甘特图
- ✅ **无消息通知**: 目前依赖页面查看；后续加WebSocket实时推送
