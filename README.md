# 家具展厅 - 安装预约与验收回单系统

## 项目概述

针对家具展厅当前靠订单表、到货群和手写验收单撑住基本盘的痛点，重新设计的业务流程系统。重点解决：
- 定制配置、到货和安装预约衔接松散问题
- 异常单处理依赖截图和电话确认的低效模式
- 入口散、提醒弱、历史难找三大核心问题
- 安装预约和验收回单之间的接力感缺失

## 技术栈

**后端**
- NestJS 10 + TypeScript
- TypeORM 0.3 + SQLite（可无缝切换到 PostgreSQL）
- 模块化架构，每个业务域独立

**前端**
- Vue 3 + TypeScript + Vite
- Pinia 状态管理
- Element Plus UI 组件库
- Vue Router 路由管理

## 核心业务模型

### 数据实体关系

```
客户 (Customer) 1--* 订单 (Order)
订单 1--* 订单项 (OrderItem)
订单 1--* 安装预约 (InstallationAppointment)
订单 1--* 验收回单 (AcceptanceRecord)
订单 1--* 异常单 (ExceptionOrder)
订单 1--* 样品借出 (SampleLoan)
异常单 1--* 补件 (RepairPart)
系统 1--* 通知 (Notification)
系统 1--* 操作日志 (ActivityLog)
```

### 订单状态流转

```
待确认 → 已确认 → 生产中 → 已到货 → 安装中 → 已完成
                                      ↓        ↑
                                    异常 → 异常处理
```

### 角色分工

| 角色 | 职责范围 | 工作台关注 |
|------|----------|------------|
| 展厅经理 | 全流程监督、异常仲裁、验收审批 | 全局数据、异常单、验收单 |
| 销售顾问 | 客户跟进、订单创建、样品借出 | 自己的订单、客户信息、样品催还 |
| 安装协调 | 安装调度、预约管理、补件跟进 | 安装日历、待安装订单、补件状态 |
| 安装师傅 | 现场安装、进度上报 | 今日安装、任务详情 |

## 核心功能亮点

### 1. 工作台按角色分流

- 每个角色登录后看到不同的待办任务和数据统计
- 任务按优先级排序，紧急事项自动置顶
- 点击任务直接跳转到对应的处理页面

### 2. 联动日历视图

- 月视图展示所有安装预约，不同状态颜色区分
- 点击日期查看当日所有预约详情
- 支持一键确认、开始安装、完成安装等连续动作
- 改期功能保留历史记录，可追溯调整原因

### 3. 订单全流程接力

- 订单详情页展示完整的业务时间线
- 每个节点（预约、安装、验收、异常）可直接操作
- 自动流转状态，减少人工干预
- 所有操作留痕，历史可追溯

### 4. 异常处理闭环

- 支持8种异常类型：样品未归还、缺件、质量问题、安装问题、客户投诉、发货延迟、定制配置问题、其他
- 异常单可关联补件需求，追踪补件全流程
- 异常解决后自动恢复订单流程

### 5. 样品借出全生命周期

- 登记借出、设置预计归还日期
- 自动识别逾期，显示逾期天数
- 一键催还，记录催还次数和内容
- 押金管理、归还状态跟踪

### 6. 智能提醒系统

- 按角色推送任务提醒
- 支持紧急/高/中/低四个优先级
- 未读消息计数，一键全部已读
- 点击通知直接跳转处理页面

## 实现取舍

### 1. 数据库选择
- **当前实现**：使用 SQLite，无需额外安装，开箱即用
- **取舍原因**：降低部署门槛，方便快速验证
- **切换 Postgres**：修改 `app.module.ts` 中的数据库配置即可，实体和查询逻辑无需改动

### 2. 认证机制
- **当前实现**：通过请求头 `X-Operator` 模拟用户身份，前端通过下拉切换角色
- **取舍原因**：聚焦业务流程验证，避免在认证上花太多时间
- **后续扩展**：可接入 JWT + 角色权限控制（RBAC）

### 3. 实时通知
- **当前实现**：前端轮询（30秒）获取最新通知
- **取舍原因**：WebSocket 会增加复杂度，轮询满足基本需求
- **后续扩展**：接入 WebSocket/SSE 实现实时推送

### 4. 文件上传
- **当前实现**：验收照片字段预留，未实现实际上传
- **取舍原因**：聚焦核心业务流程
- **后续扩展**：接入对象存储（OSS/S3）实现照片上传

### 5. 短信/微信通知
- **当前实现**：仅系统内通知
- **取舍原因**：需要对接第三方服务，增加外部依赖
- **后续扩展**：通知实体已预留 channel 字段，可扩展多通道通知

## 后续可扩展方向

### 业务扩展
1. **供应链对接**：与工厂生产系统对接，自动同步生产进度
2. **物流跟踪**：接入物流信息，自动更新到货状态
3. **数据分析**：安装时效分析、异常类型统计、客户满意度报表
4. **移动端**：开发小程序/H5，方便安装师傅现场上报进度
5. **财务对接**：对接财务系统，自动生成应收应付

### 技术优化
1. **微服务拆分**：订单、安装、验收、异常等可拆分为独立服务
2. **事件驱动**：使用消息队列（RabbitMQ/Kafka）实现业务事件解耦
3. **缓存层**：Redis 缓存热点数据，提升查询性能
4. **读写分离**：主从数据库分离，提升系统吞吐量
5. **监控告警**：Prometheus + Grafana 实现系统监控和告警

## 核心 API 接口

| 模块 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 订单 | GET | /api/orders | 获取订单列表 |
| 订单 | GET | /api/orders/:id | 获取订单详情 |
| 订单 | PUT | /api/orders/:id/status | 变更订单状态 |
| 安装 | GET | /api/installations/calendar/view | 获取日历视图数据 |

| 安装 | PUT | /api/installations/:id/reschedule | 改期 |
| 验收 | POST | /api/acceptances | 创建验收回单 |
| 验收 | PUT | /api/acceptances/:id/rectify | 整改完成 |
| 异常 | GET | /api/exceptions | 获取异常列表 |
| 异常 | POST | /api/exceptions | 登记异常 |
| 样品 | GET | /api/samples/overdue/list | 获取逾期样品 |
| 样品 | PUT | /api/samples/:id/remind | 发送催还提醒 |
| 通知 | GET | /api/notifications | 获取通知列表 |
| 通知 | GET | /api/notifications/unread/count | 获取未读计数 |
