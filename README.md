# 礼品定制-售后补单与退款处理系统

## 快速启动

### Web 模式（推荐，无需安装 Rust）
```bash
# 1. 安装依赖
npm install

# 2. 启动开发服务器
npm run dev

# 3. 打开浏览器访问 http://localhost:1420
```

### Tauri 桌面端模式（需要 Rust 环境）
```bash
# 1. 安装依赖
npm install

# 2. 启动 Tauri 开发模式
npm run tauri:dev
```

## 角色切换说明

系统支持三种角色，在页面右上角的"当前角色"下拉菜单切换：

### 1. 项目商务（张明）
**权限范围：**
- 查看所有订单和售后进度
- 发起售后补单/退款申请
- 添加订单备注
- 查看完整历史追溯链

**典型操作场景：**
- 在工作台查看待处理事项
- 收到客户反馈后，在订单详情页发起售后
- 在历史追溯页查看完整责任链

### 2. 打样跟单（李芳）
**权限范围：**
- 审核售后申请（通过/拒绝）
- 处理退款流程（审核通过→开始处理→完成）
- 查看打样版本变更历史
- 确认版本一致性

**典型操作场景：**
- 在售后处理页审核待审核的申请
- 在订单详情页查看打样版本记录
- 处理退款相关的审核和处理流程

### 3. 仓配协调（王强）
**权限范围：**
- 登记发货信息
- 执行补单发货操作（审核通过→开始处理→完成）
- 扫码录入快递单号
- 管理拆单发货

**典型操作场景：**
- 在扫码录入页扫描快递单快速关联订单
- 在订单详情页登记发货
- 处理已审核通过的补单申请

## 售后状态流转规则（防止越级操作）

```
待审核(pending) → 已审核(approved) → 处理中(processing) → 已完成(completed)
                       ↓
                    已拒绝(rejected)
```

**各角色可操作的状态：**
- **项目商务**：仅能发起申请，不能审核或处理
- **打样跟单**：pending→approved/rejected（审核）；approved→processing（退款开始处理）；processing→completed（退款完成）
- **仓配协调**：approved→processing（补单开始处理）；processing→completed（补单完成）

## 核心功能说明

### 1. 工作台
- 统计卡片展示订单概览
- 待处理事项根据角色动态显示
- 最近动态展示全系统操作记录

### 2. 订单列表
- 支持按状态筛选
- 支持搜索订单号、客户、产品名称
- 展示售后状态标识

### 3. 订单详情
- **订单信息**：基础信息、打样版本、状态
- **发货记录**：拆单发货全程记录，每批数量、快递、操作人
- **售后记录**：补单/退款统一展示，处理日志完整追溯
- **历史追踪**：从创建到完成的所有操作记录，含责任人

### 4. 售后处理
- 补单与退款统一列表
- 支持按类型、状态、快捷筛选
- 快捷筛选"待我处理"自动匹配角色权限

### 5. 扫码录入
- 支持摄像头扫码（条形码/二维码）
- 支持手动输入单号
- 扫描结果自动匹配订单
- **快速发货**：扫码后一键写入订单发货记录（不再只是弹窗）

### 6. 历史追溯
- 全链路历史记录集中展示
- 支持按订单、角色、操作类型筛选
- 异常统计：版本覆盖风险、拆单发货记录、责任链完整度

## 已修复的问题

### 1. 发货登记条件写反
**问题**：`!shipmentForm.value.trackingNo` 条件写反，导致有单号时反而不能提交
**修复**：改为 `shipmentForm.value.trackingNo && shipmentForm.value.quantity > 0`
**位置**：[OrderDetail.vue](file:///Users/liu/Documents/private/model-test/trae-test-4/src/views/OrderDetail.vue#L383-L393)

### 2. 扫码页快速发货只弹窗不写入
**问题**：`quickShip` 函数只 alert 弹窗，没有真正写入订单数据
**修复**：调用 `appStore.updateShipment` 真正写入发货记录，计算剩余数量自动发货
**位置**：[Scan.vue](file:///Users/liu/Documents/private/model-test/trae-test-4/src/views/Scan.vue#L175-L194)

### 3. 补单/退款按钮状态判断错误（越级完成风险）
**问题**：
- 运算符优先级问题：`A || B && C` 实际执行为 `A || (B && C)`，导致 warehouse 角色在 reorder 类型下任何状态都能看到"完成"按钮
- 退款单缺少 `approved` → `processing` 的"开始处理"按钮
- `canProcessAfterSale` 函数未正确判断退款单在 `approved` 状态的处理权限

**修复**：
- 加括号修正优先级：`(A || B) && C`
- 增加退款单在 `approved` 状态的"开始处理"按钮（打样跟单角色可见）
- 更新 `canProcessAfterSale` 函数，退款单在 `approved` 和 `processing` 状态都可处理
**位置**：[OrderDetail.vue](file:///Users/liu/Documents/private/model-test/trae-test-4/src/views/OrderDetail.vue#L131-L157)

## 边界说明（当前轻量实现的部分）

### 1. 数据持久化
- **当前**：使用内存存储（Pinia），刷新页面数据重置
- **建议**：后续接入 Tauri 的 fs API 或 SQLite 做本地持久化

### 2. 扫码功能
- **当前**：支持 qr-scanner 库，Web 模式需 HTTPS 或 localhost
- **建议**：Tauri 模式可调用系统摄像头 API，体验更好

### 3. 用户认证
- **当前**：角色切换为演示模式，无真实登录
- **建议**：接入账号系统，支持多用户真实权限控制

### 4. 文件上传
- **当前**：样品照片、凭证等仅做文字记录
- **建议**：增加图片上传功能，关联到订单和售后单

### 5. 消息通知
- **当前**：仅在工作台展示待办事项
- **建议**：增加系统通知、邮件/短信提醒功能

### 6. 打印功能
- **当前**：无打印模板
- **建议**：发货单、售后单等单据打印功能

### 7. 数据导出
- **当前**：无导出功能
- **建议**：支持订单、售后记录导出 Excel

### 8. 报表统计
- **当前**：仅基础统计卡片
- **建议**：增加按时间维度、客户维度、问题类型维度的统计分析
