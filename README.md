# 茶叶经销-库存盘点与损耗上报系统

## 一、快速启动

### 1. 安装依赖
```bash
npm install
```

### 2. 初始化演示数据
```bash
npm run seed
```
> 执行后会生成 `tea_inventory.db` 数据库文件，包含完整的演示数据（5个用户、3个仓库、10个产品、13个库存批次、5个盘点计划、5份损耗报告、15条操作日志等）

### 3. 启动前后端服务
```bash
npm run dev
```
> 前端: http://localhost:5173  
> 后端API: http://localhost:3001

## 三、核心业务链路演示

### 标准流程：盘点 → 损耗 → 审批 → 库存调整

```
创建盘点计划 → 执行盘点（录入实际库存） → 发现盘亏 → 一键生成损耗报告
    ↑                                                           ↓
    |                                                仓管审核损耗报告
    |                                                           ↓
    |                                                负责人审批通过
    └──────────────── 自动扣减对应批次库存 ────────────────────┘
```

### 演示数据中的完整链路示例
1. **盘点计划「2024年1月白茶仓月度盘点」**（状态：已完成）
   - 盘点后发现白毫银针批次 B20231001 盘亏 1.5kg
   - 一键生成损耗报告 LR202401003

2. **损耗报告 LR202401003**（状态：已审批）
   - 上报人：李销售（sales1）
   - 审核人：陈仓管（warehouse1）
   - 审批人：王总（manager）
   - 责任归属：仓储责任
   - 审批通过后自动扣减库存 1.5kg

3. **操作日志** 中可查看全过程的状态变化、责任人、前后值对比

## 四、重点问题处理方案

### 1. 批次混发问题
- 所有库存按 `inventory_batches` 批次追踪，每个批次独立管理入库时间、成本价、剩余数量
- 出库、损耗都必须关联具体批次 ID，系统自动按批次扣减
- 库存页面支持「汇总视图」和「批次视图」切换，批次视图可查看每一批次的完整出入库流水

### 2. 活动价口径乱问题
- `price_adjustments` 表记录每次价格变动：类型（日常价/活动价/批发价）、时间区间、审批人
- 产品详情侧边栏展示完整价格历史曲线
- 出库时关联当时的价格类型，统计时按价格口径自动归类

### 3. 损耗责任归属不清晰
- 每个损耗项独立记录 `responsibility`（公司/仓储/业务/第三方/个人）和 `responsible_person_id`
- 损耗报告支持三级审批：上报 → 审核（仓管确认事实） → 审批（负责人确认责任和成本）
- 操作日志完整记录每一步的意见和决策人

### 4. 时间顺序混乱
- 所有关键操作都写入 `operation_logs`，包含：操作人、操作时间、操作类型、前后值变化 JSON
- 盘点、损耗详情页底部展示完整时间线
- 操作日志页面（仅负责人可见）可全局追溯所有变更

### 5. 盘点与损耗联动
- 盘点详情页发现盘亏后，点击「生成损耗报告」自动带入盘亏数据（产品、批次、数量、仓库）
- `loss_reports.related_stock_take_id` 建立物理关联
- 损耗报告审批通过后自动扣减对应批次库存，无需人工二次录入

## 六、已做轻量处理的边界（待后续迭代）

### 1. 认证安全
- 当前使用固定 JWT_SECRET，生产环境需改为环境变量
- 未实现 Token 刷新机制，过期需重新登录
- 密码使用 MD5 简单哈希，生产环境建议 bcrypt

### 2. 并发与事务
- 库存扣减未使用数据库事务，极端并发下可能出现超卖
- 未实现乐观锁，多人同时编辑同一盘点单可能覆盖

### 3. 数据权限
- 当前仅按角色做功能级权限，未实现数据级行权限（如业务员只能看自己的客户）
- 仓库隔离仅做了前端隐藏，后端未强制校验

### 4. 导入导出
- 未实现 Excel 批量导入盘点数据、导出损耗报表
- 当前仅支持手动逐条录入

### 5. 消息通知
- 损耗报告状态变更未实现站内信/邮件通知
- 盘点截止提醒未实现

### 6. 附件上传
- 损耗照片、盘点签字等附件功能未实现
- 当前仅支持文字备注

### 7. 统计报表
- 看板仅实现核心指标，未支持自定义时间区间、多维度交叉分析
- 未实现损耗趋势、盘点准确率等分析图表

## 八、常见问题

**Q: 执行 npm run seed 报错？**
A: 检查是否已安装 better-sqlite3，如遇编译问题可尝试：`npm rebuild better-sqlite3`

**Q: 前端启动后接口 404？**
A: 确认后端服务已启动（端口 3001），vite.config.js 中代理配置正确

**Q: 如何重置演示数据？**
A: 删除 `tea_inventory.db` 文件，重新执行 `npm run seed`
