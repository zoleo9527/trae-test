# 桶装水配送管理系统

订水路线与司机签收管理平台 - 解决桶装水配送过程中送水、回桶、月结对不上的问题。

## 项目背景

传统桶装水配送依赖订水电话、路线表和空桶统计表手工操作，存在以下痛点：
- 送水、回桶和月经常对不上
- 异常单处理依赖截图和电话确认
- 配送站长、司机、客服三者信息不同步
- 空桶数量争议大、签收照片难追溯
- 客诉补送响应不及时

## 技术栈

- **前端**: Nuxt 3 + TypeScript + Vue 3
- **后端**: FastAPI + Python 3.10+
- **数据存储**: 内存数据库（演示用）

## 快速开始

### 方式一：一键启动（推荐）

```bash
# 安装所有依赖
npm run install:all

# 同时启动前后端
npm run dev
```

### 方式二：分别启动

```bash
# 1. 启动后端服务
cd backend
pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8000

# 2. 启动前端服务（新开终端）
cd frontend
npm install
npm run dev
```

## 核心功能

### 1. 双栏详情台设计

所有核心业务页面采用双栏布局，左侧列表、右侧详情：
- 路线列表 → 路线详情 + 订单列表
- 异常列表 → 异常详情 + 处理操作
- 客户列表 → 客户详情 + 历史订单

### 2. 配送路线管理

- 查看今日所有配送路线及进度
- 路线状态追踪（待出发/进行中/已完成）
- 配送顺序可视化
- 一键开始/完成路线

### 3. 司机签收

- 订单详情展示（客户信息、欠桶数）
- 实送桶数、回收空桶数录入
- 签收人签名
- 自动生成签收照片（演示用随机图）
- 空桶交易流水自动记录

### 4. 异常处理

**支持的异常类型：**
- 送水数量不足
- 空桶数量争议
- 客户不在
- 桶身损坏
- 地址错误
- 其他

**异常处理流程：**
1. 司机在配送端上报异常（附照片）
2. 客服在异常中心查看并处理
3. 记录解决方案，标记已解决
4. 关联订单状态自动更新

### 5. 空桶对账

- 客户押桶/欠桶实时统计
- 送水/回收交易流水
- 欠桶预警（超出押桶数量提醒）
- 按客户筛选交易记录

## 刻意简化的部分

本版本为演示原型，以下部分做了简化：

### 1. 数据存储
- ❌ 未使用真实数据库（MySQL/PostgreSQL）
- ✅ 使用 Python 字典做内存存储
- ❌ 无数据持久化（重启后端数据重置）

### 2. 认证安全
- ❌ 无 JWT Token 机制
- ✅ 简单的用户名密码验证
- ❌ 无权限中间件
- ✅ 前端 localStorage 存储登录状态

### 3. 文件上传
- ❌ 无真实图片上传功能
- ✅ 使用 picsum.photos 随机图片模拟
- ❌ 无文件存储服务（OSS/S3）

### 4. 消息通知
- ❌ 无短信/APP推送
- ❌ 无站内消息系统
- ✅ 异常状态通过页面刷新展示

### 5. 地图导航
- ❌ 无地图集成
- ❌ 无路线规划算法
- ✅ 按预设顺序展示配送点

### 6. 财务管理
- ❌ 无在线支付
- ❌ 无发票管理
- ✅ 仅记录订单金额

### 7. 移动端适配
- ❌ 未做移动端响应式优化
- ✅ 桌面端双栏布局为主

## 生产环境建议

如需投入生产使用，建议补充：

## 常见问题

**Q: 前后端端口冲突？**
A: 后端默认 8000，前端默认 3000，不会冲突。如需修改，分别在 uvicorn 启动参数和 nuxt.config.ts 中配置。

**Q: 登录不上？**
A: 确认后端服务已启动，检查 http://localhost:8000 是否可访问。

**Q: 数据保存不了？**
A: 演示版使用内存存储，重启后端会重置数据。

**Q: 签收照片不显示？**
A: 演示使用 picsum.photos 随机图片，需要联网访问。
