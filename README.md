# 手作烘焙坊 - 预订接单与产能排期系统

## 项目概述

这是一个为手作烘焙坊设计的预订接单与产能排期管理系统，旨在解决门店日常运营中预订、排产、退款、改单等业务链路断裂问题，实现门店主理人、后厨负责人、客服三角色协同作业。

## 技术栈

- **前端框架**: React 18 + TypeScript
- **构建工具**: Vite 5
- **状态管理**: Zustand 4
- **路由**: React Router DOM 6
- **样式**: Tailwind CSS 3
- **图标**: Lucide React
- **数据持久化**: LocalStorage

## 核心功能

### 1. 工作台
- 待办事项提醒（待审核订单、改单申请、退款申请、逾期订单）
- 今日数据统计卡片
- 最近订单列表
- 异常事项高亮提醒

### 2. 订单管理
- 多维度筛选（状态、急单、逾期）
- 搜索功能（订单号、客户姓名）
- 点击订单卡片打开右侧处理台
- 状态标签直观显示

### 3. 产能排期
- 按日期查看排期
- 产能饱和度显示
- 待排期订单列表
- 点击排期项打开订单详情

### 4. 数据复盘
- 订单完成率统计
- 退款原因分析
- 商品销量排名
- 原料损耗预估
- 异常事项统计

### 5. 右侧处理台
- 快速操作（状态变更、改单/退款审批）
- 商品明细查看
- 内部沟通记录
- 异常状态高亮提示

## 角色差异

### 门店主理人
- 可以看到所有页面
- 可以审核订单
- 可以审批改单和退款申请
- 可以查看数据复盘

### 后厨负责人
- 看不到数据复盘和系统设置
- 可以安排排期和更新生产状态
- 可以查看产能排期

### 客服
- 只能看到工作台和订单管理
- 不能审核订单
- 不能审批改单和退款

## 刻意简化的部分

本次演示版本做了以下简化：

1. **无真实后端**：所有数据存储在浏览器 LocalStorage 中，刷新页面后数据保留
2. **无真实认证**：使用预设测试账号，前端模拟登录，无密码加密
3. **简化的产能算法**：仅按日订单数限制，不包含复杂的排班优化和时间冲突检测
4. **无文件上传**：沟通记录中的附件仅做展示，无真实上传功能
5. **无实时推送**：状态变更需要手动刷新页面查看，无 WebSocket 实时通知
6. **简化的权限控制**：仅做前端路由级控制，无后端权限校验
7. **无新订单创建**：演示版本暂不支持创建新订单，仅可操作现有演示数据
8. **无真实支付**：退款流程仅做状态变更，无真实支付接口对接

## 数据重置

如需恢复初始演示数据，可以：

1. 登录系统
2. 进入「系统设置」页面
3. 点击「重置数据」按钮
4. 确认后页面会自动刷新，恢复初始演示状态

或者直接在浏览器控制台执行：

```javascript
localStorage.clear();
location.reload();
```
