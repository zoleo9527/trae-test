# 苗木基地养护巡查与病害上报系统

## 系统概述

本系统旨在解决苗木基地业务链路碎片化问题，实现**养护巡查 → 病害上报 → 补苗协商**的完整业务闭环。通过明确的角色分工和状态流转，让基地负责人、养护员、销售跟单各自清楚该处理哪一段，避免信息断层和扯皮。

---

## 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue 3 + Vite + TypeScript + Element Plus | 响应式管理后台 |
| 后端 | NestJS + TypeScript + TypeORM | 企业级Node.js框架 |
| 数据库 | PostgreSQL | 关系型数据库 |
| 接口规范 | RESTful API + DTO校验 | 参数自动校验 |

## 业务模型与角色

### 👥 角色体系

| 角色 | 职责 | 典型操作 |
|------|------|----------|
| 🏠 基地负责人 | 全局管控、病害确认、方案审批 | 确认病害、审批补苗方案、查看报表 |
| 🌱 养护员 | 日常巡查、病害上报、执行处理 | 提交巡查记录、上报病害、执行防治措施 |
| 💼 销售跟单 | 客户对接、协商发起、交付跟进 | 发起补苗协商、确认销售意见、跟进交付 |

### 🔗 核心业务链路

```
地块管理
    ↓
养护巡查 (养护员)
    ├─ 正常 → 完成记录
    └─ 发现病害 → 病害上报
            ↓
病害处理 (基地负责人)
    ├─ 确认病害
    ├─ 安排防治
    ├─ 记录时间线
    └─ 严重情况 → 启动协商
                ↓
补苗协商 (销售 + 基地)
    ├─ 销售提交意见
    ├─ 基地反馈方案
    ├─ 确认补植数量/品种/日期
    └─ 关闭或执行
```

### 📊 状态流转

**病害状态**: `已上报` → `已确认` → `处理中` → `已解决`

**协商状态**: `待处理` → `协商中` → `已确认` → `已关闭`

## 快速开始

### 前置要求

- Node.js >= 18
- PostgreSQL >= 14
- 数据库已创建：`nursery`

### 1. 安装依赖

```bash
# 根目录执行，安装前后端所有依赖
npm run install:all
```

或分别安装：

```bash
cd api && npm install
cd ../web && npm install
```

### 2. 配置数据库

编辑 `api/.env`:

```env
DB_HOST=localhost
DB_PORT=5432
DB_USERNAME=postgres
DB_PASSWORD=your_password
DB_DATABASE=nursery
PORT=3000
```

### 3. 初始化数据（种子数据）

```bash
# 创建测试数据，包含正常流和问题流
npm run seed
```

种子数据会自动创建以下业务场景：

| 场景 | 说明 | 状态 |
|------|------|------|
| 🟢 正常流程 | 银杏蚜虫，5天内完整解决 | ✅ 已解决 |
| 🔴 问题流程 | 红叶石楠叶斑病，逾期17天未处理 | ⚠️ 已逾期 |
| 🟡 复杂协商 | 桂花根腐病，已确认补植30棵 | 🔄 处理中 |
| 🟠 进行中 | 广玉兰介壳虫，正在协商交付方案 | 🔄 协商中 |

### 4. 启动服务

```bash
# 启动后端 (端口 3000)
npm run dev:api

# 另起终端启动前端 (端口 5173)
npm run dev:web
```

### 5. 访问系统

- 前端地址：http://localhost:5173
- 后端API：http://localhost:3000/api

## 核心功能说明

### 🔍 多条件筛选

所有列表页均支持多条件组合筛选，可连续处理动作：

| 模块 | 筛选条件 |
|------|----------|
| 巡查列表 | 地块、养护员、状态、是否有病害、日期范围 |
| 病害列表 | 地块、状态、严重程度、病害类型、上报人、是否逾期、日期范围 |
| 协商列表 | 关联病害、状态、发起人、日期范围 |
| 地块列表 | 名称、区域、品种、养护员 |

### ⏱️ 逾期自动检测

- 重度病害：1天未确认自动标记逾期
- 中度病害：3天未确认自动标记逾期
- 轻度病害：3天未确认自动标记逾期

### 📝 完整时间线

所有状态变更均自动记录时间线，包含：
- 操作人
- 操作动作
- 处理说明
- 时间戳

避免翻截图、找语音，过程全部留痕。

### 🔄 状态流转控制

前端会根据当前状态自动显示可流转的下一状态，避免误操作。

## 当前实现取舍

### ✅ 已实现的核心价值

1. **业务链路闭环**：巡查 → 病害 → 协商 完整打通，不再碎片化
2. **角色视角清晰**：各环节操作入口明确，知道该处理什么
3. **过程全留痕**：时间线自动记录，避免扯皮
4. **多条件筛选扎实**：支持组合筛选，连续处理高效
5. **逾期自动提醒**：主动发现问题，不是等客户投诉

### ⚠️ 有意简化的部分

1. **无鉴权系统**：当前未做登录/权限控制，假设内部系统信任使用
2. **无附件上传**：病害照片、语音等附件功能未实现
3. **无消息推送**：状态变更未做实时通知，需主动刷新查看
4. **无分页加载**：数据量不大时直接全量加载
5. **无编辑/删除**：业务数据一旦提交不允许修改删除，保证严肃性
6. **无客户管理**：客户信息未独立建模，仅在协商意见中体现

### 🚀 后续可扩展方向

#### 短期（1-2周）

1. **权限系统**：基于角色的访问控制（RBAC）
2. **图片上传**：病害现场照片，支持时间线带图
3. **消息通知**：微信/短信/站内信提醒待办事项
4. **导出功能**：巡查记录、病害统计导出Excel
5. **分页查询**：数据量增长后的性能优化

#### 中期（1-2月）

6. **客户管理**：独立客户档案，关联订单
7. **装车单集成**：现有装车单接入，病害直接关联批次
8. **电话回访记录**：客户沟通记录结构化存储
9. **统计报表**：按品种/区域/病害类型统计分析
10. **移动端适配**：养护员现场手机填报

#### 长期（3月+）

11. **GIS地图**：地块位置可视化，病害热力图
12. **AI识别**：拍照自动识别病害类型
13. **预测模型**：基于历史数据预测病害高发期
14. **多租户**：支持多个基地独立管理
15. **财务集成**：索赔、补苗成本核算

## 常见问题

### Q: 数据库连接失败？
A: 检查PostgreSQL是否启动，确认`.env`配置正确，数据库`nursery`已创建。

### Q: 前端API请求失败？
A: 确认后端已启动（端口3000），检查Vite代理配置。

### Q: 种子数据执行失败？
A: 先确保数据库表已创建（NestJS启动时`synchronize: true`会自动建表）。

### Q: 如何重置数据？
A: 重新执行`npm run seed`即可清空并重建所有测试数据。

## 开发规范

- TypeScript 严格模式，禁止使用 `any`
- 接口参数使用 DTO + class-validator 校验
- 数据库操作使用 TypeORM Repository 模式
- 前端使用 Composition API + `<script setup>`
- 时间处理统一使用 dayjs
